WHY
I started using n8n because Zapier billed me $800 in one month
Fair-code, self-hostable, no per-execution fees — and what that actually means
The Real Reason
A client's lead form went viral on Facebook. Zapier processed 45,000 tasks in three days. My bill was $847. That's when I understood the structural problem with per-execution pricing: it punishes success. n8n self-hosted costs the same whether you run 100 workflows or 100,000. That's not just cheaper — it's a fundamentally different business model.

n8n is fair-code licensed (source-available, self-hostable). The license allows unlimited self-hosting with no per-execution fees. You can run it on a $6/month VPS and process as many workflows as your server can handle. The tradeoff: you maintain the server.

What "fair-code" actually means

n8n uses the Sustainable Use License for hosted/commercial use — you can't build a competing product on top of it. But for internal use, client work, and self-hosted deployments, it's effectively open source. Read the license at n8n.io/legal before building commercial products on top of it.

n8n vs the alternatives — the honest positioning

Zapier is better for non-technical teams that need quick, simple integrations and don't expect volume. Make (formerly Integromat) sits in the middle — visual, credit-based, no self-host. n8n is for technical operators who want control, need volume, or are building complex AI workflows that require custom code and data transformations. If you're reading this Grimoire, n8n is probably for you.

↺ What I learned the hard way

Don't build client systems on a pricing model that punishes success. n8n inverts that equation. The only limit is your server — which you control. The only ongoing cost is the VPS — which doesn't scale with usage. Once you internalize this, you start building bigger, bolder automations. Because the cost of running them is the same as the cost of not running them.

⛑️ Full post-patch checklist

1. Pull and restart: docker pull n8nio/n8n:1.121.0 + docker-compose up -d
2. Rotate every credential stored in n8n — GHL, OpenAI, SMTP, Stripe, webhooks, OAuth tokens.
3. Add N8N_BLOCK_NODE_ACCESS=true to your .env (blocks filesystem node access).
4. Put n8n behind a reverse proxy (Nginx/Caddy). Never expose port 5678 directly.
5. Add IP allowlisting for admin routes (/rest/, /settings) in your proxy config.
6. Set N8N_SECURE_COOKIE=true and N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true.
7. Enable daily automated database backups. You need them before an incident, not after.
8. Audit your webhook URLs — remove any with no authentication.

Nginx reverse proxy config (hardened)

# /etc/nginx/sites-available/n8n
server {
  listen 443 ssl;
  server_name n8n.yourdomain.com;

  # Block admin REST API from non-whitelisted IPs
  location ~ ^/rest/(settings|users|credentials) {
    allow 203.0.113.10;   # your office IP
    deny all;
    proxy_pass http://localhost:5678;
  }

  # Webhooks — public
  location /webhook/ {
    proxy_pass http://localhost:5678;
    proxy_set_header X-Real-IP $remote_addr;
  }

  # Editor UI — auth required (handled by n8n)
  location / {
    proxy_pass http://localhost:5678;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}

M1
Self-hosting n8n — the complete setup
Docker, PostgreSQL, Nginx, SSL, backups, and why SQLite will betray you
The Mistake I Made First
I started with SQLite because it was easy. Two months later, the database corrupted during a power outage. I lost 47 workflows and three weeks of execution logs. A client was mid-campaign. PostgreSQL is not optional for production. This is not a recommendation — it's a prerequisite.

Prerequisites

Minimum Server

2 vCPU, 2GB RAM

DigitalOcean Droplet or Hetzner CX21. Hetzner is half the price for equivalent specs. I run 4 clients on a $12/mo server.

Required Software

Docker + Compose v2

apt install docker.io docker-compose-plugin on Ubuntu 22.04. Compose v2 uses docker compose (no hyphen).

DNS

A record → server IP

n8n.yourdomain.com → your VPS IP. SSL needs DNS propagation (5–30 min). Do this first before installing anything.

Ports

80, 443, 22 open

Block port 5678 from public access. n8n runs internally; Nginx proxies it to 443. Never expose 5678 directly.

Automated backups

backup.sh — runs daily via cron
#!/bin/bash
# Run: crontab -e → 0 3 * * * /root/backup.sh

DATE=$(date +%Y%m%d-%H%M)
BACKUP_DIR=/root/backups
mkdir -p $BACKUP_DIR

# Dump PostgreSQL
docker exec n8n_postgres pg_dump -U n8n n8n > $BACKUP_DIR/n8n-db-$DATE.sql

# Archive n8n config files
tar -czf $BACKUP_DIR/n8n-data-$DATE.tar.gz /root/n8n_data

# Upload to S3 (optional but recommended)
aws s3 cp $BACKUP_DIR/n8n-db-$DATE.sql s3://your-bucket/n8n-backups/

# Prune backups older than 14 days
find $BACKUP_DIR -name "*.sql" -mtime +14 -delete
find $BACKUP_DIR -name "*.tar.gz" -mtime +14 -delete

echo "Backup complete: $DATE"
⚡ Caddy is easier than Nginx for SSL

If you're not already comfortable with Nginx, use Caddy. Caddyfile: just write n8n.yourdomain.com { reverse_proxy localhost:5678 } and Caddy handles SSL automatically via Let's Encrypt. No certbot, no renewal crons. I switched after fighting Nginx cert renewal for the third time.

↺ What I'd do differently

Start with PostgreSQL from day one, even for local testing. The migration path from SQLite to Postgres is painful — you have to export workflows (JSON), export credentials (only partially — secrets don't export), rebuild the database, and re-enter credentials manually. It's a half-day of work. Postgres from the start costs nothing extra. SQLite is a trap.

The n8n data model & expressions
The mental model that explains everything — items, nodes, the execution context
The Concept That Changes Everything
I spent two weeks building n8n workflows without understanding what $json actually referred to. I thought it was "the data." It is — but it's the data of the current item, from the previous node. Once I understood items and the execution context properly, every confusing behavior suddenly made sense. This is the module I wish I'd read first.

The item model

n8n passes data between nodes as an array of items. Each item has a json property (your data) and optionally a binary property (files). Understanding this is fundamental.

What a node receives and emits

The expression context variables

Expressions use {{ }} mustache syntax. Inside expressions, you have access to these variables:

Common expression patterns

Expressions in practice
// String interpolation
Hello {{ $json.firstName }},
Your booking for {{ $json.propertyAddress }} is confirmed.

// Conditional value
{{ $json.budget >= 2000 ? 'HOT' : 'WARM' }}

// Date formatting
{{ $now.toFormat('dd MMM yyyy') }}          // "14 May 2026"

// Array operations
{{ $json.tags.includes('vip') }}
{{ $json.items.length }}
{{ $json.items.map(i => i.name).join(', ') }}

// Access upstream node data
{{ $node["Webhook"].json.body.email }}
{{ $node["Get Lead Score"].json.score }}

// Skip side effects in test mode
{{ $execution.mode === 'manual' ? 'test@example.com' : $json.email }}

The Code node — when expressions aren't enough

Code node — full JavaScript access
// Code node runs JS. Access all items:
const items = $input.all();

// Process and return transformed items
return items.map(item => {
  const { email, firstName, budget, move_in_date } = item.json;
  
  // Calculate days until move-in
  const daysUntil = Math.ceil(
    (new Date(move_in_date) - new Date()) / (1000 * 60 * 60 * 24)
  );
  
  // Score the lead
  let score = 'COLD';
  if (budget >= 2000 && daysUntil <= 30) score = 'HOT';
  else if (budget >= 1500 || daysUntil <= 60) score = 'WARM';
  
  return {
    json: {
      ...item.json,       // preserve all original fields
      score,
      days_until_move_in: daysUntil,
      processed_at: new Date().toISOString()
    }
  };
});

// To emit a single item regardless of input count:
return [{ json: { total: items.length, processed: true } }];
ℹ️
Python support: n8n 1.0+ supports Python in the Code node. Switch the language dropdown. Access items the same way: items = _input.all(). Useful when you need pandas, datetime math, or your team is more Python-fluent.

Webhooks — the front door of every automation
Authentication, idempotency, test vs production URLs, and the scare that changed how I build
The Scare
A client's webhook endpoint was publicly exposed for three weeks with no authentication. I didn't know until someone in Romania started POSTing test data. No damage — the workflow only created test contacts in a sandbox. But I spent an anxious hour auditing every workflow. Now every webhook has authentication on day one, before anything else.

A webhook is an HTTP endpoint that triggers your workflow. The URL is https://your-n8n.com/webhook/[path]. Anyone who can POST to it runs your workflow. That's the power and the risk.

Idempotency — the problem most people ignore until it's too late

The Duplicate Contact Problem
A Typeform webhook fired twice for the same submission (Typeform's retry behavior on timeout). We created two contacts in GHL for the same person. One went through the hot-lead sequence, one sat cold. The lead was confused, the sales rep was confused. We fixed it with idempotency — check before you create.

⚡ "Respond Immediately" vs "Last Node"

Always set webhooks to "Respond Immediately" for production integrations. This returns HTTP 200 instantly, then processes the workflow async. If you use "Last Node," the calling system waits for your entire workflow to complete — which can timeout for long-running AI workflows. Typeform, Stripe, and Facebook all have short timeout windows. Return 200 fast. Process later.

↺ A mistake I kept making

I used to hardcode API keys in HTTP Request node configuration. Then I'd export a workflow to share with a client or teammate — and my keys went with it. Now every secret lives in $env.VARIABLE_NAME. Workflow JSONs can be safely shared, version controlled, and duplicated. The secrets stay in .env on the server.

M7
Data transformation nodes
Set, Edit Fields, Item Lists, Merge, Aggregate — the toolkit for reshaping data

The transformation toolkit

Set / Edit Fields

Add, rename, remove fields

The most-used transformation node. Add calculated fields, rename API response fields to your schema, remove sensitive fields before logging.

Item Lists

Merge, split, aggregate

Split a field that contains an array into separate items. Or merge multiple items into one. Essential for API responses that return arrays.

Merge

Combine data streams

Join two branches of data by a key (like SQL JOIN), wait for both branches to complete, or choose between branches. Solves the "I need data from step 2 AND step 5" problem.

Aggregate

Combine all items into one

Collapse N items into 1 with summary statistics. Use for report generation: all leads → {total: N, hot: M, converted: K}.

Sort

Order items

Sort items by a field, ascending or descending. Useful before sending batches to an API that cares about order.

Limit

Cap item count

Take only the first N items. Useful for testing (limit to 5 to test logic before running on 1,000), or for top-N report queries.

Logic & control flow — IF, Switch, Wait, Loop, Filter
How to stop building spaghetti workflows
The 50-Node Workflow
I once built a workflow with 47 nodes. It handled everything — lead scoring, CRM sync, email, WhatsApp, Slack alerts, reporting. It was a feat of engineering and a disaster of maintenance. When something broke, finding the broken node took 40 minutes. Now I follow one rule: one workflow, one job. Everything else is a sub-workflow call.

Core logic nodes

IF Node

Two-way branch

True/False paths. Conditions: equal, not equal, contains, regex match, empty, exists. Stack multiple conditions with AND/OR. Use for binary decisions.

Switch Node

Multi-way branch

Route items to N outputs based on a field value. Perfect for lead type routing: residential→team1, commercial→team2, industrial→team3.

Wait Node

Delay or pause

Wait fixed time (5 min, 3 days), until a specific datetime, or until a webhook resumes the execution. Essential for drip sequences.

Filter Node

Remove items

Discard items that don't meet a condition. Unlike IF, this doesn't branch — it just drops unwanted items and continues with the rest.

SplitInBatches

Loop over batches

Process 100 items at a time instead of all at once. Prevents API rate limit errors. Set batch size to match API's rate limit.

Execute Workflow

Call sub-workflow

Trigger another workflow and optionally wait for its result. The key to modular architecture. See M10 for patterns.

The AI Agent node — how it actually works
Tools, memory, reasoning loops, and when to use agents vs simple LLM calls

The AI Agent node is n8n's most powerful AI feature. Unlike a simple LLM call (question → answer), an AI Agent can use tools — nodes it can call to take actions — and reason over multiple steps before returning a final answer.

Agent vs LLM node — when to use each

Use LLM Node when...

Simple transformation or generation

Classify a lead, write an email, extract fields from text, summarize content. One input → one output. No tools needed. Faster and cheaper than an agent.

Use AI Agent when...

Multi-step reasoning with actions

Answer a support question by searching a knowledge base AND checking a CRM AND maybe sending an email. The agent decides which tools to use and in what order.

The reasoning loop

1

User message → Agent

Agent receives the input, plus its system prompt and available tools.

↓
2

LLM decides next action

The model reasons about what to do: call a tool, call multiple tools, or respond directly.

↓
3

Tool executes

n8n runs the tool (an HTTP Request, a vector store search, a calculator) and returns the result to the model.

↓
4

Repeat or respond

If the model needs more information, it calls another tool. If it has enough, it responds. Max iterations prevent infinite loops.

⚡ System prompt engineering for agents

Good agent system prompts have four parts: (1) Role definition ("You are a support agent for..."), (2) Constraints ("Only answer using the knowledge base tool"), (3) Escalation rule ("If confidence < 0.7, escalate to human"), (4) Output format ("Always respond in under 200 words"). RAG (Retrieval-Augmented Generation) means: before answering, search a knowledge base for relevant context, then give that context to the LLM along with the question. The LLM answers based on your data, not just its training data. This is how you build AI that knows your business.

Chunking strategy matters more than most tutorials admit

Chunk too large (>1500 tokens)
Too much noise in retrieved context. LLM gets confused by irrelevant parts of the chunk. Retrieved chunk score looks high but answer quality suffers.
Chunk too small (<200 tokens)
Not enough context per chunk. Answers are technically accurate but miss nuance. Requires retrieving more chunks to get full picture.
Sweet spot: 600–900 tokens
Enough context for coherent answers. Small enough for accurate similarity matching. Use 10% overlap to prevent critical info from being split at chunk boundaries.
Semantic chunking
Split at paragraph or section boundaries, not arbitrary token counts. For structured docs (SOPs, FAQs), split by question or heading. This is harder to implement but dramatically improves retrieval quality.

Feed every escalated Q&A back into the knowledge base as a new chunk. Your bot gets smarter from its own failures. Without this loop, your bot never improves. I added it to a production system three months late and the improvement was immediate and measurable.

Queue mode & scaling
When single-instance isn't enough — Redis, workers, and concurrency limits
ℹ️
Most people never need this. Queue mode is for high-concurrency scenarios: 100+ simultaneous workflow executions, webhook spikes, or long-running AI workflows that block the main thread. If you're running under 50 concurrent executions, default mode is fine. Read this module when you start seeing "Execution timeout" or "Queue full" errors.

How queue mode works

In default mode, n8n's main process handles everything — receiving webhooks, executing workflows, managing the UI. In queue mode, a main process handles webhooks and the UI, and worker processes execute workflows. Workers can be scaled horizontally.

docker-compose.yml — queue mode with workers
services:
  n8n-main:              # handles UI + webhook reception
    image: n8nio/n8n:1.121.0
    command: n8n start
    environment:
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      - QUEUE_BULL_REDIS_PORT=6379
      # ... all other env vars

  n8n-worker:           # handles workflow execution
    image: n8nio/n8n:1.121.0
    command: n8n worker --concurrency=10
    environment:
      - EXECUTIONS_MODE=queue
      - QUEUE_BULL_REDIS_HOST=redis
      # same DB + redis env as main
    deploy:
      replicas: 3           # 3 workers × 10 concurrency = 30 parallel executions

  redis:
    image: redis:7-alpine
    volumes: - ./redis_data:/data
    command: redis-server --appendonly yes
    restart: unless-stopped

Concurrency limits

Worker concurrency
--concurrency=N — how many workflows a single worker handles simultaneously. Default: 10. Increase with more RAM. Memory-heavy AI workflows: use 3–5.
Workflow-level limit
Set in workflow settings → "Max concurrent executions." Prevents one high-volume workflow from saturating all workers.
Per-workflow throttle
Use a Wait node at the start of high-volume workflows to space executions: Wait 500ms between items when processing large batches.
