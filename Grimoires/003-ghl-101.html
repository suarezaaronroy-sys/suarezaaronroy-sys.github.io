M1
Account Setup
The decisions you make at setup compound forever

GHL has two account layers: the Agency account (your master login) and Sub-accounts (one per client or brand). This distinction matters more than most new users realize — it controls billing, data isolation, white-labeling, and what you can automate at scale.

Agency vs Sub-Account

LayerWhat it controlsWho manages it
Agency AccountBilling, white-label domain, user permissions, sub-account creationYou (the operator)
Sub-AccountCRM, contacts, pipelines, workflows, calendars, funnels — all client-specific dataYou or delegated client access
⚡ Power Tip 001

Never build in the Agency account directly. Always create a sub-account first — even if it's just for testing. Anything built at the agency level is harder to move, harder to isolate, and harder to hand off. Start clean.

White-Label Setup

GHL allows full white-labeling under the SaaS Pro plan ($497/mo). You can brand the platform as your own — custom domain, logo, login page, email sender domain. If you're reselling GHL seats, this is non-optional.

// Minimum white-label setup checklist
Agency Settings:
  ☑ Custom domain configured  (DNS A record + GHL domain settings)
  ☑ Email sender domain verified (SPF + DKIM + DMARC)
  ☑ Agency logo + brand colors set
  ☑ White-label app name set

Sub-Account defaults:
  ☑ Default timezone set (affects all scheduled sends)
  ☑ Business address set (CAN-SPAM / GDPR footer requirement)
  ☑ Reply-to email address verified

M2
Sub-Account Structure
One sub-account per client. One source of truth per contact.

A sub-account is a fully isolated GHL environment. Contacts, pipelines, workflows, calendars, and funnels in one sub-account have no visibility into another. This is the right architecture for agency work — each client's data is isolated by default.

⚡ Power Tip 002

Plan your sub-account structure before you build anything. Merging contacts across sub-accounts is painful. If a business has multiple brands that share a contact list, that's one sub-account. If they're genuinely separate businesses, that's two.

Snapshot System

GHL Snapshots let you export a sub-account's entire configuration — workflows, funnels, pipelines, custom fields, email templates — and import it into a new sub-account. This is how you productize your builds.

Snapshot includes:
  ✓ Workflows (with trigger logic preserved)
  ✓ Funnels and websites
  ✓ Email / SMS templates
  ✓ Custom fields and values
  ✓ Pipeline stages
  ✓ Calendar configurations

Snapshot excludes:
  ✗ Contacts and CRM data (by design)
  ✗ Active campaign enrollments
  ✗ API keys and third-party credentials
  ✗ Reputation management reviews
Build with snapshots in mind. If you build a Grimoire-quality system for one client, the snapshot is how you replicate it. Name your workflows, funnels, and custom fields descriptively — "Landlord D0 Sequence" not "Workflow 1".
M3
CRM + Contacts
The contact record is the source of truth. Treat it like one.

GHL's CRM is built around Contact records. Every automation, every workflow, every pipeline stage — all of it anchors to a Contact. Getting the contact data model right is the most important structural decision in a GHL build.

Custom Fields

GHL supports custom fields on both Contacts and Opportunities. The single-owner rule applies: every field should have one source of truth — one workflow, one form, or one integration that writes to it. If two workflows both write to lead_score, you'll get race conditions.

Field TypeBest Used ForNotes
TextNames, addresses, free-form notesSearch-indexed
NumberLead score, deal value, property countSortable in Smart Lists
DropdownStatus, wing, segment, temperatureUse for anything that needs filtering
DateMove-in date, last contacted, contract signedEnables date-based workflow triggers
CheckboxConsent flags, feature flags, boolean statesGDPR consent fields — checkbox, not text
File UploadDocuments, photos, signed contractsStored in GHL CDN
⚡ Power Tip 003

Group your custom fields before you create them. GHL lets you organize fields into groups. Plan your groups first (e.g., "Lead Qualification," "Property Details," "Automation State"). An ungrouped field list at 50+ fields becomes unusable in weeks.

Tags — The Segmentation Engine

Tags in GHL are free-form labels that live on a Contact record. They're the most flexible segmentation tool in the platform — and the most abused. Without a tag taxonomy, you'll have 200 tags that nobody can interpret six months later.

// Tag taxonomy template — use this naming convention
SOURCE: Source: organic_seo | Source: paid_facebook | Source: referral
WING:   Wing: landlord | Wing: renter
STATUS: Status: hot | Status: warm | Status: cold | Status: suppressed
SEQ:    Sequence: active | Sequence: completed | Sequence: paused
EVENT:  Event: replied | Event: clicked | Event: booked | Event: converted
AUDIT:  Review: needed | Duplicate: flagged

Duplicate Prevention

GHL deduplicates contacts by email address and phone number by default. A form submission with a phone number that already exists in the CRM will merge to the existing record — or create a duplicate if the phone doesn't match.

Always check for duplicates before firing Day 0 sequences. A contact who submits the same form twice can receive two copies of every automation email and SMS. Add a workflow action that checks for a [Sequence: Active] tag before enrolling — if tagged, skip or alert instead.

M4
Pipelines
A pipeline is a model of your sales process — not a wishlist

A GHL Pipeline is a series of stages that an Opportunity (deal) moves through. Contacts can be in pipelines. Opportunities are what actually move. The distinction matters: a Contact can have multiple Opportunities in multiple pipelines simultaneously.

⚡ Power Tip 004

Stage names should describe what has happened, not what you hope happens. "Proposal Sent" means a proposal was sent. "Interested" means nothing — it's a feeling, not a state. Stages that describe real events make pipeline reports meaningful.

Pipeline Trigger Logic

// Workflow trigger: Opportunity Stage Changed
Trigger: Pipeline Stage = "Consultation Booked"
Action 1: Send confirmation email (template: consultation-confirm)
Action 2: Send SMS reminder (24h before — use Wait step with date field)
Action 3: Create task: "Review lead score before call"
Action 4: Assign to owner if unassigned

// Common mistake: triggering on stage name string match
// Stage names change. Use the stage ID where possible, or lock stage names.

M5
Workflows
GHL's automation engine — triggers, conditions, actions, branches

Workflows are the automation engine in GHL. A Workflow has a trigger (what starts it), conditions (if/else logic), actions (what happens), and optional wait steps (delays between actions).

Workflow Architecture Rules

RULE 1: One workflow, one job.
  Don't build "mega workflows" with 40 steps covering 3 different scenarios.
  Split by function: Day-0-Landlord, Day-3-Follow-Up, Booking-Confirmed.
  Single-job workflows are testable, debuggable, and replaceable.

RULE 2: Name everything descriptively.
  Bad:  Workflow 1 | New Automation | Copy of Copy of Test
  Good: [Landlord] D0 - Instant Response | [Renter] Day 3 - Case Study

RULE 3: Always add a loop guard.
  Check for [Sequence: Active] tag at step 1 of any enrollment workflow.
  If tagged: stop or route to alert. Prevents double-enrollment on re-submission.

RULE 4: Test with a real contact before going live.
  Create a test contact. Submit the trigger form manually.
  Watch the workflow execute in real time. Fix before touching real leads.

RULE 5: Use Wait steps for time-sensitive sends.
  Don't rely on scheduled time in the action itself.
  Use a Wait step → then Send. This gives you a cancel window.
⚡ Power Tip 005

The "Go to Workflow" action is your escape hatch. When a contact needs to leave one sequence and enter another (e.g., replied → exit nurture → enter hot sequence), use Go to Workflow. It's cleaner than building branching logic inside a single workflow.

⚡ Power Tip 006

Set up error notifications. Workflows can fail silently — wrong field name, API timeout, rate limit hit. Enable the GHL workflow error notification email. Check it daily until you're confident the system is stable.

⚡ Power Tip 007

"Contact Tag Added" is the most versatile trigger in GHL. You can fire a tag from any workflow, any Zap, any API call, or any n8n node — then build a separate workflow that reacts to that tag. This creates a clean decoupled architecture where systems talk through tags instead of nested logic.

Key Action Types

Communication

Send Email / SMS / WhatsApp

Use templates for consistency. Always verify sender domain before any bulk send. Check footer compliance (unsubscribe link, physical address).

CRM

Update Contact Field / Add Tag / Remove Tag

The state-management layer. Write lead scores, temperatures, sequence days. Tags drive triggers in other workflows.

Pipeline

Move Opportunity to Stage

Drives pipeline reporting. Combine with a Create Task action so there's always a human-visible record of why the stage changed.

Routing

Go to Workflow / Remove from Workflow

Cross-workflow routing. Use to exit sequences cleanly. Remove from Workflow stops all pending wait steps and scheduled actions.

M7
SMS + Email
Deliverability is not optional — it's the whole game
Configure compliance before any sequence fires. Every email needs an unsubscribe link. Every SMS needs STOP handling. These are not optional — they're legal requirements (CAN-SPAM, TCPA, GDPR, PECR).

Email Deliverability Setup

// Minimum deliverability checklist — do this before any send
DNS Records:
  ☑ SPF record added to sending domain
  ☑ DKIM configured (GHL provides the DNS record)
  ☑ DMARC policy set (start with p=none, monitor, then enforce)

GHL Settings:
  ☑ Unsubscribe link active in all email templates
  ☑ Physical business address in email footer
  ☑ Reply-to address is a real monitored inbox
  ☑ Suppression list configured and syncing in real time

Before any bulk send:
  ☑ Send to internal test address — verify all tokens populate
  ☑ Check mobile render (most opens are mobile)
  ☑ Verify unsubscribe link works end-to-end
  ☑ Monitor open rate first 2 hours — below 15% = pause and audit
⚡ Power Tip 008

GHL's email infrastructure is shared. Your sending reputation depends partly on other GHL users on the same IP pool. If you're running high-volume cold outreach, consider routing sends through a dedicated cold email tool (Instantly, Smartlead) and using GHL only for warm/opted-in sends.

SMS Compliance

Required on every SMS campaign:
  ☑ "Reply STOP to unsubscribe" — exact text, every first message
  ☑ STOP keyword handling enabled (Settings → Phone Numbers)
  ☑ Check national DNC list before cold SMS campaigns
  ☑ Written prior consent captured before marketing SMS (TCPA)

// TCPA violation: $500–$1,500 per text. Class actions are real.
// GHL does not handle TCPA compliance for you. You handle it.

Calendar + Booking
Appointment booking as a pipeline trigger — not just a scheduling tool

GHL's calendar system handles appointment types, availability, booking pages, confirmation emails, and reminders — all natively. The key insight: treat a booking as a workflow trigger, not just a calendar event.

⚡ Power Tip 009

Connect every calendar to a pipeline stage. When an appointment is booked → move Opportunity to "Consultation Booked." When it's marked complete → move to "Evaluated." Pipeline stages driven by calendar events give you automatic tracking with zero manual data entry.

Reminder Sequence Template

  1h before:  SMS: "Your call is in 1 hour — here's the link: [meeting_link]"

M9
Funnels + Sites
GHL's page builder — when to use it and when not to

GHL has a full page builder for Funnels (single-path, conversion-focused) and Sites (multi-page, navigation-based). Both use the same editor. The choice depends on the goal: a landing page that drives one action = funnel. A multi-page website = site.

⚡ Power Tip 010

UTM parameters pass through GHL forms natively. Add hidden fields for utm_source, utm_medium, utm_campaign. Map them to Contact custom fields. Without this, you can't calculate CPL by channel — and organic traffic and paid traffic look identical in your pipeline.

⚡ Power Tip 011

Always set a canonical URL on GHL pages. GHL can generate multiple URLs for the same page (custom domain + gohighlevel.com subdomain). Without a canonical, Google may index both and split your link equity. Set canonical in Page Settings.

Funnel vs External Landing Page

Use GHL Funnel when...Use external page (Webflow, WordPress) when...
Speed to launch matters more than design flexibilityBrand consistency with an existing site is required
You want native GHL form → CRM → workflow connectionSEO is a primary traffic source (GHL page SEO is limited)
A/B testing is built into the funnel stepComplex page interactions or animations are needed
M10
Forms + Surveys
The entry point for every lead. Build it like one.

GHL Forms are the bridge between your landing pages and your CRM. A form submission creates a Contact record (or updates an existing one) and can fire any workflow trigger.

Form Best Practices

MOBILE-FIRST FIELD ORDERING:
  Above fold: 2 fields max (email + city, or name + phone)
  Below fold: additional qualification fields
  Reason: micro-form reduces abandonment 30–50% on cold traffic

HIDDEN FIELDS (mandatory for attribution):
  utm_source   → maps to Contact.utm_source
  utm_medium   → maps to Contact.utm_medium
  utm_campaign → maps to Contact.utm_campaign
  These populate from URL params automatically — zero user effort.

COMPLIANCE FIELDS:
  Consent checkbox (GDPR/TCPA) — NOT pre-ticked
  Privacy policy link — visible, not buried
  Label: "I agree to receive marketing communications..."

DUPLICATE PREVENTION:
  On submit → Workflow: check for [Sequence: Active] tag
  If active → skip enrollment, log duplicate attempt
  If not → proceed with Day 0 sequence
⚡ Power Tip 012

Add a backup email notification on every form. In Form Settings, add a notification email to your personal inbox. It fires independently of GHL automations — so if GHL has an outage, you still get lead alerts. Setup: 5 minutes, cost: zero.

GHL's social planner and reputation management — what's actually useful

GHL includes a Social Planner (schedule posts to Facebook, Instagram, GMB, LinkedIn) and a Reputation Manager (request and monitor Google/Facebook reviews). Both are useful for keeping clients in-platform — but neither replaces a dedicated social tool for high-volume content.

Review requests are the highest-ROI automation in GHL. Set up a post-close or post-delivery workflow that sends a review request SMS 24h after the job is done. A simple "How did we do? [Google review link]" sent at the right moment converts at 20–40%. Most businesses never send it at all.

M12
Payments
The one rule that matters: gate on payment.cleared, never payment.submitted

GHL supports native payments via Stripe and PayPal integrations. You can collect one-time payments, recurring subscriptions, and payment plans — all connected to your pipeline and workflows.

The most expensive GHL mistake. Using payment.submitted (card details entered) as your fulfillment trigger instead of payment.cleared (funds confirmed). Submitted ≠ cleared. Cards decline. Payments fail. Gate everything on payment.cleared — no exceptions.
⚡ Power Tip 014

Create a "Payment Failed" workflow. When a subscription payment fails, GHL can trigger a workflow. Use it: send an SMS alert, pause service delivery, and route to a collections sequence. Without it, failed payments disappear into silence.

PAYMENT EVENT WORKFLOW TRIGGERS:
  payment.cleared   → ✓ Move to Closed-Won, fire fulfillment, send receipt
  payment.submitted → ⚠ Do NOT use for fulfillment (not cleared yet)
  payment.failed    → Fire: payment failed SMS + email, pause delivery
  subscription.created → Start retention sequence
  subscription.cancelled → Fire: cancellation flow, offboarding

Voice AI 2026
GHL's native AI phone agent — what it does, what it can't do yet

Voice AI is GHL's native AI phone calling system. It handles inbound and outbound calls using configurable conversation pathways. As of 2026, it replaces basic use cases previously handled by third-party tools like Bland AI — but requires careful pathway architecture.

Voice AI — What's Actually Available (2026)

Native AI voice calls inside GHL

Voice AI runs on GHL's infrastructure — no Twilio setup required for basic use. Pathways define how the AI handles different conversation branches: greeting, qualification questions, objections, booking handoff.

Cost model: Usage-based on top of your plan. Track per-call cost in your unit economics. High-volume outbound campaigns can add $100–500+/mo to your GHL bill.

Pathway Prerequisites

Before activating Voice AI on any workflow:
  ☑ Call pathway built and tested (test mode available)
  ☑ Transfer-to-human trigger configured (if score or intent threshold hit)
  ☑ Recording consent language in opening script (varies by state/country)
  ☑ Call costs estimated and budgeted
  ☑ Fallback if AI fails: route to voicemail or human queue

Pathway structure template:
  STEP 1: Greeting + identification (< 10 seconds)
  STEP 2: Qualification question 1 (city / property type)
  STEP 3: Qualification question 2 (timeline / urgency)
  STEP 4: If score meets threshold → offer booking
  STEP 5: If pushback → objection pathway
  STEP 6: Close with next step or transfer to human
Recording consent varies by jurisdiction. US two-party consent states (CA, FL, IL, WA, others) require both parties to consent to recording before the call begins. The opening script must include consent language. This is not handled automatically by GHL.

Agent Studio 2026
Visual AI conversation builder — beyond single-response bots

Agent Studio is GHL's visual builder for multi-step AI conversation flows. It connects natively to GHL contact data — the AI can look up a contact's name, pipeline stage, or custom field values during a conversation.

What Agent Studio Does

Multi-turn AI conversations

The AI can ask follow-up questions, branch based on responses, and hand off to a human or workflow based on what it learns. Goes beyond static FAQ bots.

Current Limitations

Still maturing in 2026

Complex reasoning chains are better handled in n8n + Claude API. Use Agent Studio for structured conversation flows — not for tasks that require nuanced judgment.

↺ Honest assessment — Agent Studio vs n8n + Claude API

Agent Studio is easier to set up and stays inside GHL. n8n + Claude API gives you far more control, better reasoning quality, and lower per-call cost at volume. For simple lead qualification bots: Agent Studio. For AI that needs to make judgment calls, reference previous conversation history, or handle edge cases: n8n + Claude.

M18
QA + Debugging
A system that can fail silently is not a system — it's a liability

GHL workflows fail in predictable ways: wrong field names, missing merge tags, rate limit hits, API timeouts, duplicate enrollments. The QA system below catches these before they reach real contacts.

Pre-Launch QA Checklist

FORMS:
  ☑ Submit test form — verify Contact created with correct tags and fields
  ☑ Check UTM fields populated (utm_source, utm_medium, utm_campaign)
  ☑ Verify Day 0 sequence fired within 5 minutes
  ☑ Duplicate test: submit form again → verify no double enrollment

SEQUENCES:
  ☑ Check all merge tags render correctly (not: {{contact.first_name}})
  ☑ Verify unsubscribe link active in every email
  ☑ SMS: verify STOP response triggers suppression
  ☑ Test behavioral trigger: reply → sequence pauses immediately

PIPELINE:
  ☑ Stage change → correct workflow fires
  ☑ Opportunity moves to correct stage on booking
  ☑ Closed-Won trigger fires fulfillment workflow

PAYMENTS:
  ☑ Use Stripe test mode — simulate successful payment
  ☑ Verify payment.cleared (not payment.submitted) fires fulfillment
  ☑ Simulate failed payment — verify failure workflow fires

WEEKLY HEALTH CHECK (15 min):
  ☑ Submit test form both wings — sequence fires correctly?
  ☑ Check workflow error notification email — any failures?
  ☑ GHL Campaign stats — any deliverability issues?
  ☑ Review new contacts — tags and custom fields populated?
⚡ Power Tip 018

The Workflow History tab is your first debugging tool. Every workflow execution is logged — you can see exactly which step failed, what the contact data looked like at that moment, and what action was skipped. When something goes wrong, check History before changing anything.

↺ The most common GHL failure I've seen in real builds

Workflows edited live without testing. A single change to a merge tag name, a trigger filter, or a wait duration can silently break every future enrollment. Make changes in a test workflow first. QA the test. Copy the fix to production. It takes 10 extra minutes and has saved hours of cleanup every time.
